优先级

bool=char<unsigned char<short<unsigned short<int<unsigned int <long lonng<unsigned long long<float<double
这一条链可以分成两层，从int断开，凡是低于int的在参与算数运算时都会带来整数提升
例如定义：short a=1;
shortb=2;
auto c=a+b; //实际上是int c=a+b;

char d=4;
bool e=0;
auto f=a+e; //int f=d+e;

在主流的32/64-bit platform
bool[0-1]
char[-128-127]
shor[-32768-32767]
unsigned short[0,65535]
int [-2147483648,2147483647]
int可以覆盖所有低级别的取值范围，最终推导类型不会超过int

在16-bit platform
unsigned short的最大值65535直接超过了16位的int的上限32767，编译器将触发底层的兜底机制，将其强制推导为16-bit 的unsigned int[0,65535]

第二层链是寻常算数转换，编译器会沿着类型优先级链向上比对，将低位类型隐式拔高，与高位严格对齐后再进行运算。
例如int(16bits)+double(32bits)→double(32bits)+double(32bits)

auto的三大原则
1.浮点型>整型
long long a=100;
float b=3.14f;
auto c=a+b; //float c=a+b;
尽管long long的内存空间更大，也具有极高的整数精度，但是为了保住浮点数的数值上限和小数属性
2.宽度优先原则
3. 无符号大于有符号原则
无符号和有符号的混合运算遵循二进制补码原则
负数a会被编译器强制按照无符号数重新解释

八位微缩模型展示
int a=-5; 11111011
unsigned int a=251; 11111011

unsigned int b;
auto c=a+b;
完全取决于无符号数b的大小
如果b的值较小，b等于3时并不足以突破无符号数的上限，因为没有发生溢出饶回，最终会保留这个非预期的极大值导致计算错误
b等于10，相加的结果会超过无符号数容量上限，触发底层的截断机制，丢弃进位，产生溢出饶回，绕回的截断数值刚好与预期的数学结果5完全一致，从而制造了毫无bug的假象。
