迭代式阻塞服务器

发表于2026-11-08|更新于2026-11-11|项目
|浏览量:

这个迭代式阻塞服务器在第一个listen监听状态的Linux服务器基础上又分为了两个阶段

第一阶段是确认可以连进来：

增加了错误检查、SO_REUSEADDR、打印对端IP和端口、打印fd。
代码展示

迭代式阻塞服务器：iterative单线程串行处理：
accept····处理····close·····再accept。
可以理解为排队，第2个客户必须等第1个客户走。
与它相反的是并发式concurrent，意思是同时服务多个：fork多线程、pthread多线程、或者epoll单线程多路复用。这是这一项目在后面阶段要做的事情。

第一阶段做了什么：从内核的队列里，把一条已经建立好的连接取出来，换成一个可以操作的编号。
客户端connect()→内核完成三次握手→连接被放进accept queue（全连接队列）→accept（）
值得注意的一点是accept不参与握手。握手发生在连接进入队列之前，由内核独立完成。所以即使程序卡在别的地方，根本没有调用accept，客户端依然能connect成功——连接只是等待去获取。
accept不创建连接，只是暴露一个已经存在的连接。

代码说明
#include <arpa/inet.h>提供inet_ntop和INET_ADDRSTRLEN，如果漏掉编译时会报：未声明标识符
if(lfd<0)等三处判断，是每个系统调用后立刻检查返回值，失败就perror打印原因并退出。如果不写的话，失败的话程序不会像做算法题那样立刻报错，照常运行，错误推迟几十行暴露，实际工程中检查难度飙升。
sockaddr_in cli{}; 作用是输出参数，由内核填写对端的IP和端口，空初始化可以避免垃圾值。没有这一语句的话会出现乱码IP。
socklen_t len=sizeof(cli) 作用是输入输出参数，相当于进去时告诉内核给你的缓冲区是多大，回来时实际填写了多少。必须初始化为sizeof，否则内核可能写越界或者返回-1。
int cfd=accept(lfd,(sockaddr*)&cli,&len);取一条连接，返回新的fd。队列空时阻塞。
inet_ntop(AF_INET,&cli.sin_addr,ip,sizeof(ip));将32位二进制IP转化为“127.0.0.1”字符串
ntohs(cli.sin_port)网络字节序→主机字节序，和htons互为逆运算。如果不写的话端口会显示成13000多。
close(cfd)作用是放走这个客户，回收fd。如果不写的话会连接一万次后Too many open files。

accept的三大误区解释：

返回的是新fd，不是lfd：
---

lfd代表的是监听这个行为，即使一条连接都没有它也会一直存在；cfd代表的是某一条具体连接，随着连接建立而建立，随着close而销毁。
lfd=3 //一直是3
cfd=4//第1个连接
cfd=5//第2个连接（如果同时还有一个终端开着）
这是socket编程最容易搞混也是最有趣的地方：
我需要读数据我就用cfd，我想继续引入新的我就lfd，绝对不能用lfd去read，会返回错误。

队列空的时候，线程是在睡和等：
----

没有连接进来时，进程进入TASK_INTERRUPTIBLE状态，挂在socket的等待队列上面，完全不占用CPU，有连接进来时，内核会把它唤醒。
我们继续加深对阻塞的理解：不是死循环空转，而是主动让出CPU睡觉，CPU占用率0。假如我们写while(1){if(有连接)···}称之为忙等（busy-waiting），CPU会烧到100%却什么也没干。阻塞式IO 的价值就在于它把等的成本交给了内核调度器。

为什么cfd总是4：
----

Linux的分配fd的策略是取最小可用编号（lower available）。0、1、2是终端，2是lfd，所以第一个cfd必然是4。
close(4)之后4就空出来，下一条连接拿到的就还是4，这是分配策略。
如果想看到5，有一个办法，就是开两个终端，同时nc且都不退出，让分配策略去分配5。因为4还占着位置，第二个只能拿5。

阶段缺陷：

第1个缺陷：串行 一个客户端连上不说话（比如telnet挂着），后面的连接全部排队。（需要项目后面的线程池/主从Reactor来修补）
第2个缺陷：无数据通路 accept完成后立刻close，不能接收也不能发送 。下一步是要添加read/write做echo。
第3个缺陷：全阻塞 一次只能守一个fd，无法同时监视多个。解决方法就是后面的epoll多路复用。
第一个缺陷的连带后果是if(cfd<0){perror(“accept”);continue;}这一行如果被信号打断（errno==EINTR）会立刻再进accept，形成瞬间的空转。在该阶段不是关注的重点，但是后面做信号处理时要着重处理。

第二个阶段是处理数据：

增加内层读写循环，服务器第一次能接收能发送，能处理多轮消息。
代码展示

七个系统调用：socket,setsockopt,bind,listen,accept,read,write,close。
其余全是错误检查、地址填充和打印。

#include <sys/socket.h> //这是socket/bind/listen/accept/setsockopt的声明。不带.h的C++头文件是std::流输入输出，带.h的是C的格式化输入输出。
#inlcude <netinet/in.h> //sockaddr_in、htons、INADDR_ANY都在这里。
#include <unistd.h> //read、write、close的声明，这是POSIX的通用系统调用。
#include//printf、perror

int lfd=socket(AF_INET,SOCK_STREAM,0);三个参数：AF_INET用IPv4；SOCK_STREAM用有连接的字节流（TCP）；0让内核自己选协议（TCP）。返回的是一个fd（文件描述符），不是连接本身，此刻它既没有连上任何人，也没绑定任何地址，只是一个空壳。

if (lfd<0){perror(“socket”);return 1;}
//错误检查

socket返回的fd是进程fd表里的一个索引，指向内核里的socket对象。在/proc/PID/fd/里面能看到它指向socket:[inode]。
