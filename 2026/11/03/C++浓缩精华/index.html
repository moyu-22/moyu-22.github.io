C++浓缩精华

发表于2026-11-03|更新于2026-11-07|学习
|浏览量:

C++的应用领域

–3A游戏：引擎与实时渲染
–操作系统内核：系统软件
–Chromium：浏览器内核
–高频交易：低延迟系统
–自动驾驶：实时计算
–PyTorch底层：AI计算框架

认识C++

程序的运行：
main.cpp
#include /引入标准输入输出声明/ //如果main函数前写using namespace std;就可以不用标注std::
int main() /程序入口/
{
std::cout<<”Hello World!”<<std::endl; /输出文本并换行/
return 0; /向宿主环境报告运行成功/
}
编译与解释：
–C++编译型–
源码→本机机器码→执行
–Python解释型–
源码→解释器/字节码虚拟机→执行
编译流程：
1.0预处理 #include处理头文件内容→iostream预处理后形成翻译单元→#define 宏定义 文本层面的替换
2.0编译（检查语法和类型）→中间表示/汇编（具体取决于工具链）→编译错误（缺分号/类型不匹配/未声明）
3.0汇编 汇编代码→机器码→main.o 目标文件，尚未完成的外部符号解析→每个源文件 通常分别编译成目标文件
4.0 链接 组合目标文件与库/A.o调用B.o 解析跨文件符号引用/声明却未实现undefined reference/排错入口（区分编译错误与链接错误）

变量对应真实存储

变量 类型+值+存储
内存空间 对象占具体字节
抽象层不同，Python也使用内存，但是对开发者隐藏更多细节

C++的坑点

1..有符号整数溢出
32位int表示-2147483648~2147483647
溢出后不保证变负数，正确做法是加法前解决边界，或者提升到足够宽的类型再计算
2..整数除法
5/2结果为2
5.0/2结果为2.5
3..未初始化局部变量，读取前未赋值，而全局变量自动初始化为0（声明时永远顺手初始化也不是一个好习惯）

标准流与文件流

std::cin>>x 键盘读取变量
std::cout<<x 变量输出到屏幕
std::ifstream/std::ofstream 文件输入输出
控制流 if/for/while/Switch

内存四大区

代码区：编译后的机器码，通常只读
全局/静态区：全局变量、static静态存储期（与程序共存亡）
堆:动态分配、显式管理生命周期（手动管理的自由空间）(谁负责释放)
栈：函数工作区，自动存储期（自动管理的函数工作区）（谁负责回收）
堆和栈的深度学习在数据结构与算法

动态分配的内存

申请newT→使用（对象保持存活）→释放deleteP
堆的自由伴随释放责任（自由指生命周期可控）
<动态内存事故>
内存泄露 占用未归还未释放
旧指针p 0x1000已经被delete P还去访问，生命周期已结束了
重复delete P

指针（C/C++最有趣的地方）

指针是保存对象的地址，地址是位置，实际数据在目标对象那里
指针通常8 bytes
传递地址，让函数操作同一个对象
调用方：原对象–数据保留在原位置
被调用函数：接收一个地址，通过指针访问原对象，不用深拷贝整个对象
这也是它性能极强的答案，毕竟能传一个8字节大小地址就能解决的事情，比花资源去拷贝几百MB的原对象来得轻松

空指针状态
int* p=nullptr；不指向任何东西的指针，判空是必要检查之一。
野指针状态
int* p；未初始化，值不确定的指针，没有合法地址。
还有一个悬空指针的概念。
检查过程：
声明时，没有值就赋值nullptr；
使用前，if(p!=nullptr)
释放后，delete P；P=nullptr；

数组名在多数表达式中指向首元素的指针
A[0] A[1] a[2]
A[i]=*(A+i)
从首地址往后跳i个元素
0表示偏移量为0

内存对齐

struct s{
char c; int n;};
struct的内存大小大于成员大小之和，成员之间的空隙也计入sizeof。

引用（指针的温和版替代品）

原名：变量 别名：引用（起外号）
int a=10;
int& r=a;(同一对象的两个名字，a与r访问同一个对象)

传参小口诀

小类型就传值，大对象用const只读
需要修改原物引用指针，表达“无对象”空指针

const：让接口表达只读约束
修饰变量 const int n=10; 表明n不可以被重新赋值。
修饰参数 void read(const &x) 不能通过x修改对象。
修饰成员函数 int size()cost; 限制修改非mutable成员

总结一下：栈自动，堆手动，指针保存地址，引用起外号，只读const。

对象与类

class player{
//数据
//行为
};
一份实际存在的对象，
成员变量→对象的数据
成员函数→对象的行为
class Player{ 对外行为attack（）攻击
int hp; takeDamage（）受伤
int attackPower; isDead（）判断死亡
};
struct与class的功能一样，但是struct默认公开，class默认私有，权限不一样。
（struct打包数据，class强调行为与封装）
public private friend（友元函数或类）
构造函数与析构函数（创建对象与销毁对象）
构造函数准备初始化列表
析构函数~Player（）
在对象销毁时瞬间自动执行，释放内存，关闭文件，断开连接

拷贝：用已有对象创建新对象
对于普通数据没有数据，如果成员有裸指针，拷贝的是指针存储的地址，如果释放时，相当于原实际数据被释放两次，造成重复释放。
现代C++更推荐使用标准容器和智能指针来管理资源，不然必须析构+拷贝构造+拷贝赋值+移动构造+移动赋值的五法则

this:当前对象是谁
void Player::takeDamage(int damage){
this->hp-=damage;
static:全类共享一份
继承：子类继承父类
public外部与子类均可访问
protected仅子类可访问
private均不能访问
菱形继承（二义性）和虚继承（共享一份基类对象）

多态
virtual：调用实际对象
class Character{
public:
virtual void attack();
};
void Boss::attack(){/…/}
/声明与重写/
实际调用
character* p=&boss;
p->attack();
纯虚函数是只规定接口，具体实现交给子类，纯虚函数的类是抽象类
基类析构不虚，子类资源可能泄露。

overload（重载）override（重写）
重载在同一作用域，参数不同
重写在派生类，覆盖基类虚函数

总结
数据（状态）+成员函数（行为）
封装（控制访问边界）
继承：共性复用
多态：接口统一、行为可变

RAII和智能指针

资源获取即初始化是在构造函数时获取资源，析构自动释放资源，
现代C++尽量少手写new和delete。
独占式智能指针
unique_ptr：所有权只能转移
资源由它一个占有
auto q=std::move(p);
无额外代价，运行速度极快
共享式智能指针
share_ptr:
弱引用智能指针
weak_ptr
不加计数

例如父节点用共享式智能指着强持有子节点，如果子节点用弱引用智能指针，循环就切断了，不会造成资源泄漏。
lock（）有效时就临时的share_ptr，失效时就空share_ptr，也顺便解决了悬空问题
这也是现代C++基本不手写new和delete

模版：把类型留作参数

函数模版
template
T maxof(T a,T b){return a>b?a:b;}
泛型编程，零成本针对抽象机制
类模版的典型例子：STL容器

模版元编程的深水区：递归，特化，能在编译期做图灵完备的计算

STL：容器、迭代器、算法

容器决定存储方式，算法决定处理逻辑。
动态数组vector
空间不够时申请一块约两倍大的新内存
旧数据全部搬过去 “均摊”常数时间复杂度
扩容后指向旧元素的指针和迭代器全部作废
-迭代器实效问题
缺点：中间插入删除线性时间复杂度，因为后面的元素要逐一换位置

string字符串
字符序列也是可管理的资源
拼接、查找、切片

list双向链表
和动态数组完全互补 任意位置插删常数时间复杂度，但是不支持下标，找元素要从头遍历
内存不连续，对CPU缓存极不友好
定位目标可能O(n)，性能受访问模式影响

map按比较规则组织键
有序映射，有序键值对，底层红黑树，增删查都是对数时间复杂度
顺序由compare决定，不强制从小到大
需要“排好序的字典”

unordered_map：先找桶，再找键
哈希表 平均常数时间复杂度，但无序

容器选择：需求
默认/连续访问→vector
平均快速查找→unordered_map
需要有序遍历→map

适配器：限制接口，保留规则
栈：stack 后进先出
队列：queue 先进先出
优先队列：priority_queue（VIP插队），按优先级

迭代器
“泛化的指针”
把容器连接到算法
指向当前元素，往后走一步，取值
*it //取值
++it //前进一步

现代C++

C++11及以后
auto n=12; //int
auto x=3.14; //double
推导完成类型不变，静态
与python运行时随便改变不同
for(const auto&item:items)加引用避免复制，加常量修饰表示只读

Lambda 匿名函数

方括号[]是捕获列表，把外面的变量抓进来用
[x]按值捕获 复制一份副本
[&x]按引用抓 指向外面的x本身

std::move(x) 可绑定右值的表达式 移动构造赋值

并发

多核 让任务同时完成
std::thread worker(task);
主线程→join()等待→继续执行
子线程→执行task→任务结束

互斥锁：共享区域一次只进一个线程
mutex
lock_guard可以理解成一个自动管理锁的对象
{std::lock_guardstd::mutexguard(m);
++counter;
} //guard析构，释放mutex
RAII思想在并发中的应用

原子变量
atomic：把一次操作作为整体
std::atomiccounter{0};
++counter;
对于单个变量的简单操作atomic比mutex更轻量，速度更快

async和future
更高层的异步任务抽象

std::async(std::launch::async,task)
提交任务 future凭证 get()取结果

condition_variable条件变量
可以让线程先睡眠，等条件成立再唤醒
cv.wait(lock,predicate); cv.notify_one();修改共享状态

真实项目——线程池
并发的核心原理：
可以不共享就不共享，独立数据
单变量操作atomic，检查操作边界
复杂不变量mutex，用RAII管理锁

工程化

头文件与源文件分离
math.h接口
math.cpp实现
#pragma once防止同一个头文件被重复包含

命名空间namespace，标准库中的内容均使用std这个命名空间。
std::cout就是如此，一般情况可以using namespace std;
但是最好工程实践使用std::cout，限定名让依赖者不被迫引入全部名字。

Cmake构建系统
项目的源文件少时，可以手动维护，但是一旦到达几百个，就难以手动维护。
Cmake作为一个业界工具解决了这样的问题
在Cmake中点txt文件写好构建配方，Cmake就可以按照这个配方编译整个工程，并且不同平台都可以复用。

单元测试和包管理
单元测试的两类工具：Google Test /Catch2
可以为每个模块写自动化测试，不必只靠人工检查来判断代码是否被改坏
包管理
vcpkg Conan
可以用统一的命令获取第三方库
减少手动下载源码、配置依赖和自行编译的工作

异常处理和异常安全
try、catch、throw
文件不存在和网络连接异常，运行失败等
当异常向外层传播时，沿途创建的栈对象都会正常执行析构函数，
因此文件、锁和内存等资源仍然能被自动释放
这种保证叫异常安全。

但是游戏和嵌入式有时候会禁用异常，来换取更极致的性能和更明确的执行行为
转而使用错误码std::expected<T,E>(C++23标准库设施，采用C++17的项目需要其他方案)

类型转换
static_cast 常规显式转换 double→int
dynamic_cast继承体系中的安全向下转型Base*→Derived*
指针失败返回nullptr 引用失败抛出std::bad_cast
const_cast去掉const限定
reinterpret_cast按照底层比特重新解释数据，谨慎使用

调试器
gdb和lldb可以设置断点，单步执行
AddressSanitizer地址消毒器，可以在编译时加入fsanitize address地址检查选项
自动发现数组越界、悬空指针和部分内存泄露的问题
Valgrind老牌内存检查工具

static和inline
static用于局部变量时与程序共存亡，全局变量时只在当前源文件中可见，
可以避免与其他文件中的同名内容冲突
用于类成员时表示这个成员属于类本身
inline允许同一个定义出现在多个文件中

编译期和运行期
编译期可以模版实例化、constexpr计算、类型检查
换取运行阶段的极致性能

C++因为指针才内存可控，因为资源易错有了RAII和智能指针，需要组织程序有了封装/继承/多态，需要复用逻辑减少重复工作量才有了模版和标准模版库，需要写的更安全诞生了现代C++，
利用多核有了标准并发库，需要多人协作有了工程化来构建大型项目。
